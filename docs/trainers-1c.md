# Trainers from 1C → TV screensavers (research journal)

Живой журнал направления «заставки с тренерами из 1С на ТВ». Обновлять после каждого шага, чтобы новая сессия продолжала без вопросов. Секреты — только в `.env` (переменные `FIT1C_*`), сюда не писать.

## Цель

Взять данные о тренерах из 1С:Фитнес (HTTP API), сделать красивые заставки для экранов. **Этап 1 — тест:** прототипы слайдов, прогон на экранах через обычный плейлист. **Этап 2 — внедрение в админ-панель** (модуль синхронизации + генерация слайдов) — только после того, как тест понравится.

## Источники данных

### 1С HTTP API (NeoFit Крылатское)

- Base: `FIT1C_BASE_URL` = `https://1c-krlt.n-fit.ru/Base/hs/api/v3` (IP 83.237.180.102).
- Auth: Basic `FIT1C_LOGIN:FIT1C_PASSWORD` + заголовок `apikey: FIT1C_API_KEY`. Без них — 401.
- Учётка — `admin` (полные права). Для прода нужна отдельная учётка только на HTTP-сервис. Пользователь также прислал `PASS_TOKEN_SIGN_KEY` — для нашей задачи не нужен, нигде не сохранён.
- API видит **один клуб**: `NeoFit Крылатское` (`FIT1C_CLUB_ID`). Одинцово (`1c-o.n-fit.ru`) — другая база, этих ключей там нет.

**`/trainers` (снято 2026-10-09):** 30 записей. Фото у 16, описание у 17. Мусор, который надо фильтровать: детская комната (3), сисадмины (2, вкл. «вадим приложение»), фитнес-менеджер, «Mango», три заглушки-должности («Инструктор по плаванию» и т.п. без фамилии). `department` заполнен у 8 из 30 — группировать по `position.title`.

- `photo` — URL вида `.../hs/api/v2/files/<APIKEY>/<id>-<n>.jpeg`. **Ключ в URL + требует auth (401 без него)** → приставкам напрямую отдавать нельзя, только через наш сервер (скачать, обработать sharp, отдавать свой файл).
- Фото студийные, на чёрном фоне, ~530×768, 55–75 КБ, JPEG. Для портретной карточки на 1080p хватает, на полный экран — мало.
- `description` — HTML (`<div>`, `<br>`): опыт, образование, специализация. Нужна очистка.

**`/classes`:** у 97 из 197 занятий за неделю `employee` — реальный человек из `/trainers` (19 разных). Остальное — бронь зала или сотрудник-заглушка.

### Сайт клуба

- `https://k.n-fit.ru/offer/?link=trainers` (Bitrix, шаблон `neo_fit_krylatskoye`). Публичный, без ключей.
- Карточки `div.wehave__carousel-item[data-type=training]`, в скрытом попапе `data-onecid="<GUID 1С>"` — **связь с 1С по id**. Поля: ФИО (`h2`), должность (в footer), фото (`/upload/iblock/...`, те же файлы, что в 1С: 511–567×768), «О тренере:», «Достижения:».
- **13 тренеров**, все — «Инструктор тренажерного зала».

### Сверка сайт ↔ API (2026-10-09)

Пользователь ожидал, что списки совпадают. **Не совпадают:**
- Совпало по id: **5**.
- Только на сайте: **8** (Алукриев, Горяников, Охим, Костин, Негруцкая, Ломидзе, Турашева, Колоскова) — `/trainers` их не отдаёт.
- Только в API: 25 — групповые программы, бассейн + служебный мусор (см. выше). Сайт эти направления на этой странице не показывает.
- Гипотеза (не проверена): `/trainers` отдаёт сотрудников с флагом публикации в приложении/сайте в карточке 1С; у 8 тренеров зала он не стоит. Проверить в карточке сотрудника в 1С (или спросить интегратора).
- **Все 8 «только на сайте» отдаются из 1С через `/employee?employee_id=`** (фото и описание есть у всех). То есть данные по ним в 1С есть — не хватает только их присутствия в **списке** `/trainers`. Метода, отдающего полный список тренеров зала, не нашли.

## Решения

- **2026-10-09 — источник данных только 1С.** Сайт не используется как источник данных (ФИО/фото/описание/достижения — всё из `/employee`). Объединение: список = `/trainers` (с фильтром мусора) ∪ id тренеров зала. Пока `/trainers` неполный, id 8 тренеров зала берутся разово с сайта (`data-onecid`) — только как список GUID, не как данные.

- **2026-10-09 — дизайн теста (одобрен).** Без изменений сервера/плеера: генерим PNG 1920×1080 (экраны Крылатского горизонтальные) и грузим обычными картинками.
  - `scripts/trainers-1c/fetch.js` — 1С → `scripts/trainers-1c/out/` (gitignored: ФИО/фото): тренеры (`/trainers` ∪ id зала, детали через `/employee`), расписание на день (`/classes`), фото с auth.
  - `scripts/trainers-1c/render.js` — HTML-шаблоны → PNG через локальный Chrome headless (`--screenshot`), без новых npm-зависимостей.
  - Тип 1 «карточка тренера»: фото слева (чёрный фон сливается), ФИО, направление, 3–4 тезиса (опыт/специализация/достижения). Только с фото; без фото — пока пропуск.
  - Тип 2 «Сегодня в клубе»: время · занятие · зал · тренер с аватаркой; без броней залов и заглушек; разбивка на несколько слайдов. Для теста — снимок дня.
  - Стиль: чёрный + салатовый NeoFit, крупная типографика (смотрят с 3–5 м).
  - Показ: тестовый экран «Крыло-TEST» + отдельный плейлист на `tv.n-fit.ru`, боевые экраны не трогаем. Крылатское = экраны «Крыло-ТЗ-1…4» на `tv.n-fit.ru` (там же Одинцово, 16 экранов всего).

## Хронология

- **2026-10-09** — разведка API (методы выше), выгрузка `/trainers`, `/classes`; сверка с сайтом по `data-onecid`. Ключи сохранены в локальный `.env` как `FIT1C_*`. Найден `/employee?employee_id=` — все 8 тренеров зала с сайта есть в 1С. Решено: данные только из 1С.

- **2026-10-09 — прототип готов и выложен на тестовый экран.**
  - `fetch.js 2026-10-10` → 28 тренеров (24 с фото), 29 занятий. Фильтр заглушек: у них пустое `name` (должность лежит в `last_name`).
  - `render.js` → 26 слайдов: 24 карточки + 2 «Сегодня в клубе» (суббота 10.10). Шрифты Unbounded + Manrope (Google Fonts, грузятся при рендере), фото вписаны через `mix-blend-mode: lighten`.
  - В расписании есть тренеры, которых нет в `/trainers` (Зарайский, Гопанюк, Акбутаев, Гоплачева) — показываются без аватарки.
  - На `tv.n-fit.ru` создано через `scripts/trainers-1c/server-create-test-screen.js` (app остановлен на 6 с, `pm2 stop → node → pm2 start`; при первой попытке скрипт упал на `require('dotenv')` → app простоял ~1 мин, данные не тронуты):
    - экран **«Крыло-TEST (тренеры)»** `1c46f426-d132-4769-b6ab-bbc3f9b6d706` → плеер `https://tv.n-fit.ru/player/index.html?id=1c46f426-d132-4769-b6ab-bbc3f9b6d706`
    - плейлист **`TEST-TRAINERS-KR`** `67b9c8f5-b58d-43e0-bfdc-c646344dfef7` (сначала 2× «Сегодня» по 20 с, потом 24 карточки по 12 с)
    - 26 медиа `trainers-test-*.jpg`
    - бэкап `data/*.json` до изменений: `/root/trainers-test-backup-20261009-203531/`
  - Проверено: API экрана отдаёт 26 items, headless Chrome показывает слайд в плеере, боевые плееры после рестарта опрашивают с 200.
  - **Откат:** в админке удалить экран → плейлист → медиа `trainers-test-*` (порядок важен: плейлист, назначенный на экран, не удаляется).
  - **Обновить слайды:** проще через админку (заменить медиа в плейлисте). Повторный прогон скрипта создаст ДУБЛИ экрана/плейлиста — его надо сначала доработать под update.
