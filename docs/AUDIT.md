## Confirmed bugs (требуют фикса)

### `src/modules/screens/screens.repository.js:57-69` — race в `updateLastSeen`
Метод читает `cache`, потом пишет через интервал. Два одновременных heartbeat'а могут перезаписать друг друга и потерять `lastSeenAt`. Android-плееры шлют heartbeat регулярно — реалистичный сценарий.

**Дата:** 2026-05-14. **Импакт:** low (худшее — слегка устаревший `lastSeenAt`).

### `src/modules/media/media.processor.js` — утечка `.tmp.mp4` при SIGTERM
`fs.unlink(tmpOutput).catch(() => {})` на ошибке. Если процесс убит (SIGTERM на Windows / прерывание PM2) — временный файл остаётся в `uploads/`. На Windows накапливается мусор.

**Дата:** 2026-05-14. **Импакт:** medium (заполняет диск со временем).

### `package.json:3` — версия `2.0.0-NEO` устарела
В CHANGELOG уже v3.2. `package.json` не бампали со времён v2.0-NEO (~март 2026). `/api/system/health` отдаёт устаревшую версию, в админке под кнопкой «Выйти» тоже неверная цифра.

**Дата:** 2026-05-14. **Импакт:** low (только косметика).

## Needs verification (агент сообщил, ещё не сверял глазами)

### `src/modules/auth/auth.routes.js:25` — `pendingAuth` не чистится при неверном пароле?
Недавний коммит `e3b29b9` починил «clear pendingAuth on no-2FA login», но агент пишет, что похожий путь остался для случая неверного пароля. Открыть и проверить.

### `src/modules/pair/pair.service.js` — race при генерации кода
Между `findAll()` и `create()` теоретически может быть коллизия 6-символьного кода. Маловероятно (TTL 10 мин, простор кодов широкий), но в коде есть.

### `src/modules/media/video.queue.js:78-88` — `resumeUnfinished` без try/catch
Если `processing-queue.json` повреждён, функция может бросить. Сервер не упадёт (есть `.catch()` в `server.js:177`), но очередь молча не восстановится.

### `src/modules/media/media.service.js:94-111` — orphan-записи при удалении медиа во время обработки
Если файл удалён через `DELETE /api/media/:id` пока идёт processing, callback может обновить «несуществующий» mediaId.

### `src/modules/settings/settings.service.js:6-14` — race при загрузке логотипа
Если `fs.rename` упадёт, tmpPath удалится, а старый файл логотипа останется частично перезаписан или несогласованный.

### `src/modules/backup/backup.service.js:132-145` — `spawnSync` для `tar` на Windows
Если в окружении нет `tar` (Git-Bash / WSL не установлен) — упадёт без понятного сообщения.

### Все записи в `/data/*.json` — действительно ли через `atomicWrite.js`?
Полный аудит репозиториев на предмет прямого `fs.writeFile` мимо `src/utils/atomicWrite.js`. Это критичная конвенция, проверить целиком.

## Notes (наблюдения, не обязательно к фиксу)

### `server.js:60` — `trust proxy: 1`
Корректно для одного nginx перед Node. Если когда-нибудь окажется CloudFlare/CDN перед nginx, `req.ip` начнёт врать. Сейчас ок.

### `server.js:62-78` — CSP с `'unsafe-inline'` в scriptSrc/styleSrc
Не критично без явных XSS, но при наличии бюджета на рефакторинг — вынести inline-обработчики из шаблонов и удалить `'unsafe-inline'`.

### `ecosystem.config.js:9` — `watch: false`
На проде это правильно. Просто заметить, что после изменения кода нужен `pm2 restart signage`.

### `src/modules/screens/screens.monitor.js` — `isRunning` флаг
Защита от параллельных проверок. Если одна проверка зависнет навсегда, следующие пропускаются молча. Стоит добавить таймаут с принудительным сбросом.

### `src/modules/media/media.routes.js:10` — multer пишет в `os.tmpdir()`
А потом файл перемещается в `uploads/`. На Windows это может быть медленно (разные диски / разные FS). Рассмотреть запись сразу в `uploads/_tmp/`.

### `src/modules/media/media.processor.js` — hardcoded `crf 23, preset medium`
Эти параметры — итог расследования лагов на H616 (`docs/archive/lagi.md`), менять без оснований нельзя. Но если когда-нибудь появится другой класс приставок — параметризовать через settings.

### Расхождения фронт ↔ API в admin SPA
Не проверял систематически. Часто бывает, что фронт вызывает несуществующий эндпоинт или ждёт другое имя поля — выглядит как «иногда работает, иногда нет». Стоит пройтись отдельно.
